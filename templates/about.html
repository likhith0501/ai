ℹ About the Project

AI-Based Detection of Cyber Threats in Unidirectional IP Traffic — an end-to-end machine learning pipeline that classifies network flows as normal or malicious, highlights unidirectional communication and exposes the results through a cybersecurity dashboard.

👤 Problem statement

Networks produce large amounts of flow data. Attacks that are almost entirely one-way (single-host denial of service, outbound beaconing, scanning, data exfiltration) are hard to spot with signature based tools because no reply traffic exists. Statistical learning over flow features generalises these patterns and flags suspicious flows automatically.

🎯 Objectives
  • Accept CSV traffic datasets with flexible column naming
  • Clean, encode and scale data without train/test leakage
  • Derive a traffic_direction feature and count unidirectional flows
  • Compare several classifiers using accuracy, precision, recall, F1 and ROC-AUC
  • Score new uploads through a web dashboard and a JSON API
  • Persist uploads, predictions and model metrics in SQLite

⚠ Security measures
  • Uploaded files are renamed with werkzeug.secure_filename and prefixed by a timestamp
  • Only the .csv extension is accepted; other extensions are rejected
  • Upload size is capped by MAX_CONTENT_LENGTH (413 error page on overflow)
  • Flask secret key is read from the CYBER_THREAT_SECRET_KEY environment variable, never hard-coded
  • Authentication: set CYBER_THREAT_PASSWORD to require a session login; passwords are hashed, never stored in the database
  • CSRF token required on every state-changing request; cookies are HttpOnly, SameSite and optionally Secure
  • Login throttling after repeated failures from one client
  • All database access goes through SQLAlchemy ORM queries (parameterised, no string-built SQL)
  • Uploaded content is parsed as data only — never executed
  • Errors are rendered as friendly pages instead of Python tracebacks
🔬 Limitations
  • Flow-level analysis cannot attribute an attack to a specific user
  • Encrypted traffic hides payload content, so only metadata is analysed
  • The bundled sample dataset is synthetic; real captures yield different accuracy
  • Models drift when network conditions change and must be retrained
💡 Future improvements
  • Deep autoencoders for unsupervised anomaly detection
  • Online learning with concept-drift detection
  • Optional SHAP explanations per record
  • Time-series features for beaconing detection
  • Containerised deployment with a REST gateway
